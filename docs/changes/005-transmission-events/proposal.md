# 提案：单信道 PTT 事件化与统一仲裁

> status: merged
> 变更编号：005

## 动机

当前 `EchoService` 同时承担 MQTT 接入、协议解析、防循环、流缓存、超时判定、
冲突处理和回放，职责耦合；全局缓冲也没有把 FMO 协议第 8 章的单信道路由仲裁
建模为独立机制。后续录音等能力若继续接入 Echo 内部状态，会复制超时状态机并
加剧耦合。

## 目标

1. 将一次获准占用信道的 PTT 建模为 `TransmissionCompleted` 领域事件。
2. 以单一 `ChannelCoordinator` 同时仲裁 MQTT 上行与 Echo 本地回放。
3. 保留 `EchoService` 业务名称，使其作为事件消费者和本地语音流生产者工作。
4. 实现协议 §8.4 的 1500ms 路由窗口与抢占规则，以及 §8.5 默认 60s 上行限制。
5. 为 Recorder 等后续消费者提供进程内事件接口，不引入新的 MQTT 事件协议。

## 范围

### 做

- PTT 路由仲裁、完成事件、进程内广播和服务组合根
- Echo 通过信道路由租约回放，支持被更高优先级网络流抢占
- 配置迁移、结构化事件、单元测试和真实 MQTT 回归
- 更新待实现的 change 002，使 Recorder 改为消费完成事件

### 不做

- Recorder 实现
- 跨进程事件、事件持久化或重试
- 设备侧 RF 占用提示、忙音和内部收发方向互斥
