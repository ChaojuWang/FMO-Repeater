# 详细设计：协议输入与 Echo 标识加固

> status: merged ｜ 变更编号：006

## 1. 消息包 MTU 兼容性决策

Issue #2 建议对 1400B MTU 做严格检查，但现有实现允许不可拆分的单个超长编码帧
封包并允许 Parser 读取。为最大限度兼容已经存在的发送端和录制数据，本变更不在
构造或解析边界增加检查、过滤或警告，保持当前行为。

该决策属于有意接受的协议偏差，而不是遗漏；若未来需要严格模式，应以独立配置和
增量设计引入，默认值及对历史数据的行为需另行评估。

## 2. RADPCM 恢复索引

`parse_frame()` 解包后立即校验 `0 <= step_index <= 88`，失败抛
`ProtocolError(reason="bad_step_index")`。`build_frame()` 使用相同规则，避免内部
调用者构造出解码器无法安全消费的帧。编码器自身产生的索引不受影响。

## 3. Echo 回放标识

- `echo.uid` 必须为 `1..0xFFFFFFFF`；移除值 0 的“保留原 UID”配置语义。
- `callsign_prefix` 必须非空，且 UTF-8 编码长度不超过消息头呼号字段的 12B。
- 原始呼号可在“前缀 + 原呼号”时被线格式截断，但完整前缀必须保留，因此基于
  vendor + prefix 的回环检测始终成立。
- Echo 重写始终写入配置 UID，不再保留原发送者 UID。

禁止 UID 0 同时解决设备按原 UID 自过滤而听不到回声的问题。该配置不提供静默
兼容；旧配置必须显式迁移为非零 Echo UID，启动时给出清晰错误。

## 4. 依赖契约

运行依赖改为 `paho-mqtt>=2.0,<3`，因为 `CallbackAPIVersion.VERSION2` 从 2.0 才
可用。测试环境继续允许更新的 2.x 版本，验收额外覆盖最低支持版本。

## 5. 错误与测试

新增测试覆盖：

- RADPCM parse/build 的 89、255 等非法索引返回 `bad_step_index`；
- Echo UID 0、空前缀、超过 12B 及截断多字节前缀均拒绝；
- 12B ASCII/UTF-8 边界前缀可用并能识别自身回放。

现有单帧超 MTU 兼容测试继续保留，防止本变更意外改变该行为。
