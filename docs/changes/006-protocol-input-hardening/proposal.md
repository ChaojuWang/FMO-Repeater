# 提案：协议输入与 Echo 标识加固

> status: merged
> 变更编号：006

## 动机

Issue #2 复现了 RADPCM 非法 `step_index` 泄漏 `IndexError`、Echo 标识配置在线
格式截断后无法识别自身回环等问题。运行代码还使用 Paho 2.x 回调 API，但依赖
范围允许 1.6。

## 目标

1. RADPCM 恢复点的步长索引只允许 0..88，非法输入统一为 `ProtocolError`。
2. Echo 配置生成的回放标识必须能在线格式中无损表达并可靠防循环。
3. 依赖声明与实际使用的 Paho API 保持一致。

## 范围

- 修改 RADPCM、配置校验、依赖声明及对应测试。
- 更新配置模板和存量设计文档。
- 不改变正常 OPUS/RADPCM 聚合策略，不实现 MQTT TLS 或发布确认。

## 非目标

- 不拆分 MQTT 传输组件。
- 不修改 daemon 生命周期。
- 不对超过 1400B 的消息包增加构造或解析限制；现有兼容行为保持不变。
