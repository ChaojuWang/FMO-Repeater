# 提案：回放缓存超过 max_duration 时截断

> status: merged
> 变更编号：004

## 1. 动机

单次 PTT 键控理论上可长达数分钟，若回声完整重放会阻塞信道过久、且与对讲机
「短时通联」的使用习惯不符。需要给回放加时长上限，超过上限的部分不重放。

## 2. 目标

- 触发回放时，若缓存的首包→末包接收时间跨度超过阈值（默认 30s），**只重放
  前 30 秒的包**，超出部分丢弃
- 阈值可配置：`echo.max_duration`（秒，默认 30.0）
- 不影响现有「停止收包满 timeout(2s) 回放」的触发逻辑

## 3. 语义决策

- **截断行为**：保留头部 30 秒内（含边界）的包，丢弃其后的尾部包
- **度量口径**：接收时间跨度（`monotonic` 首包到末包），简单直观、避免依赖
  包内帧时长累加带来的复杂
- **可配置**：`echo.max_duration`，默认 30.0

## 4. 范围

### 做
- `config.py`：`echo.max_duration` 配置项 + 校验（>0）
- `echo.py`：回放时按跨度截断，超出部分丢弃
- 事件：记录 `truncated` 与丢弃包数
- 测试：跨度 >30s 截断、≤30s 不截断、配置生效

### 不做
- 分片回放（把超长流切成多个 30s 段逐段回放）
- 音频级裁剪（跨帧边界精确切到 30s 整）
