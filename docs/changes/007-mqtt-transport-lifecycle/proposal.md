# 提案：MQTT 传输、发布确认与可证明停机

> status: merged
> 变更编号：007

## 动机

Issue #2 指出 Echo 只检查 `publish().rc` 就计为成功，缺少发送完成确认；MQTT
服务构造函数注册进程信号；事件消费者 join 超时后仍会断开 MQTT，无法严格保证
停机期间没有线程继续使用客户端。

## 目标

1. 将 Paho 客户端生命周期和配置集中到 `MqttTransport`。
2. 每个 Echo 包在有限时间内等待 Paho 发布完成，并准确区分成功、失败、超时和取消。
3. 支持 QoS 和发布超时配置，同时保持现有默认 QoS 0 行为。
4. 停机时先取消受控工作，再等待线程结束，最后断开 MQTT。
5. 将信号注册移到 CLI/lifecycle 层，使服务组件可在任意线程构造。

## 范围

- 新增 MQTT 传输适配器，调整 Repeater/Echo/事件总线生命周期。
- 扩展配置、模板、测试和存量设计。
- 保持 FMO 包内容、路由规则和回放节奏不变。
- 保持当前明文 MQTT 连接方式；FMO 网络暂无 TLS 升级计划。

## 非目标

- 不修改 daemon PID 管理。
- 不引入持久化消息队列或自动重试；实时语音失败后只记录，不补发迟到包。
