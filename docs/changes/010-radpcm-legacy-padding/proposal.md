# 提案：RADPCM 旧格式填充字节兼容修复

> status: merged
> 变更编号：010

## 1. 问题

现场设备的旧格式 RADPCM 帧出现 `adpcmBytes=0xE440`。低字节 `0x40` 是旧版
8-bit 字段截断后的合法值 64，高字节 `0xE4` 是未初始化填充。设备能正常播放
Echo 原样回放，但 Recorder 将 uint16 整体解释为 58432 并拒绝所有帧。

当前实现仅接受高字节为 0 的旧帧，与官方协议“以低字节判定”及 change 001 原始
设计不符。

## 2. 目标

1. 旧格式只要 `adpcmBytes` 低字节为 64，即按固定 320B 数据区解析。
2. 新格式 uint16=320 的行为不变。
3. 其他非法长度继续拒绝；帧长、数据偏移和解码算法不变。
4. 增加现场值及多种填充字节的回归测试，更新存量设计。

## 3. 非目标

- 不改变 RADPCM 编解码算法、恢复点、直流抑制或丢包逻辑。
- 不改变 Echo、Recorder、消息包或编码语音帧格式。
- 不连接线上 MQTT；由既有离线合成帧覆盖兼容行为。
